# 从节点部署与运维手册

适用：主从分流（设计见 `docs/MASTER_RELAY_NODES.md`）。主节点就是现有的 Sub2API（数据库、Redis、管理后台都在它上面）；从节点是同一个镜像用 `NODE_ROLE=relay` 启动，**不连数据库和 Redis**，只转发请求，用量和额度经主从通信交给主节点。

> 原则：转发逻辑几乎全在从节点；主从之间只有授权和计费；日志和记录留在从节点本机，后台实时向节点查询。

## 1. 准备

| 项目 | 要求 |
|---|---|
| 主节点 | 已升级到带主从分流的版本；`RELAY_MASTER_LISTEN_ADDR`（如 `:7443`）对从节点开放，**直连**，不能放在会解密的反向代理或 CDN 后面 |
| 从节点机器 | 公网 IP，443 端口对外开放（证书用 TLS-ALPN-01 申请，**不需要 80 端口**），能访问主节点的 7443 和站点地址 |
| 域名 | 每台从节点一个独立域名（如 `r1.example.com`）。解析记录由管理员在域名服务商处自己改，系统里没有任何能改解析的密钥。TTL 建议 60 秒 |
| 主节点私钥加密密钥 | `RELAY_KEY_ENCRYPTION_KEY_FILE`（内容为 64 位十六进制）。**必须显式配置、妥善保管，不会自动生成**：丢了它，已有的主从私钥解不开，所有从节点要重新激活 |

主节点环境变量（`deploy/docker-compose.yml` 的 environment 里加）：

```yaml
- RELAY_MASTER_LISTEN_ADDR=:7443
- RELAY_KEY_ENCRYPTION_KEY_FILE=/run/secrets/relay-kek
- RELAY_DOMAIN_ASK_ADDR=127.0.0.1:9002   # 给 Caddy 的 ask 接口，只能是回环地址
```

> **ask 接口和 Docker 网络（容易踩）**：ask 只允许监听回环地址（代码强制，不能放宽，否则任何能连到它的人都能探测哪些域名是从节点域名）。在 Docker **桥接网络**里，容器的 `127.0.0.1` 是容器自己的回环，宿主机上的 Caddy 访问 `http://127.0.0.1:9002/` 连不到它，`ports:` 映射也没用（映射转发到容器的网卡，不是它的回环）。结果是 Caddy 对所有按需证书都拒绝，"把从节点域名解析到主节点"这条应急路径会静默失败。要用这个功能，主节点必须满足下面之一：
> - 主节点容器用 `network_mode: host`（此时 `127.0.0.1:9002` 就是宿主机的回环，宿主机上的 Caddy 能连到；`ports:` 不再需要，直接监听在宿主机上，注意 8080 不要对外暴露）；
> - 或者 Caddy 也跑在容器里并加入主节点的网络命名空间（`network_mode: "service:sub2api"`），它们共用同一个回环。
>
> 主节点直接装在宿主机上（`deploy/install.sh` / systemd）时没有这个问题。**不满足条件时不要依赖"手动改解析到主节点"：升级时先排空，等进行中的请求结束再升级，期间这台的 API Key 用户会短暂连不上。**

并把 7443 映射出去、把密钥文件作为 secret 挂进去。主节点要把从节点配成可信代理（`server.trusted_proxies` 加上各从节点 IP）：从节点把请求交给主节点转发时，客户端 IP 放在 `X-Forwarded-For`。

## 2. 主节点：Caddy

`deploy/Caddyfile` 已带 `on_demand_tls`：从节点域名被手动解析到主节点（排空升级、故障应急）时，Caddy 先问 `http://127.0.0.1:9002/?domain=…`，**只有后台已登记的从节点域名才会放行**，其他任意域名拿不到证书。主节点对从节点域名只开放 API Key 网关接口（其余路径 404；主节点分配比例为 0 时整个 403）。`ask` 的端口要和 `RELAY_DOMAIN_ASK_ADDR` 一致。**宿主机 Caddy + 桥接网络的主节点容器，这个功能不工作**（见第 1 节的说明）。改完 `caddy validate` 再 `caddy reload`。

## 3. 部署一台从节点

1. 登录后台 → **从节点管理 → 密钥轮换 → 主从通信根证书**，复制根证书指纹；打开总开关"主从分流"（运行状态要是"运行中"，否则页面上会写原因）。
2. 在从节点机器上：

   ```bash
   cd deploy
   cp relay-node.env.example relay-node.env      # 填主节点地址、根证书指纹、站点地址
   docker compose -f docker-compose.relay-node.yml --env-file relay-node.env up -d
   docker compose -f docker-compose.relay-node.yml logs sub2api-relay | grep -i fingerprint
   ```

   日志里打印的是**这台的身份指纹**（长期密钥的公钥指纹）。从节点本机只需要主节点地址、根证书指纹、站点地址三样，其余配置全部由主节点下发。
3. 后台 **节点** 页签的"待激活"出现这台（任何人都能注册，所以待激活最多 20 台、24 小时没激活自动清除，可一键全部拒绝）。点 **激活**：
   - **指纹必须照着从节点本机日志里读到的填写**，不要复制页面上显示的那一行——名称、主机名、IP 都能被冒充，指纹是区分"自己部署的机器"和"别人注册上来的机器"的唯一依据；
   - 填对外域名，点"检查解析"：没解析到这台的注册 IP 时会提示，确认后勾"仍然激活"；
   - 带宽上限（Mbps，0 为不限）：负载按它计算，超过 85% 不再给这台分配新用户和新 Key。
4. 激活后这台自己向 Let's Encrypt 申请域名证书（缓存在数据卷 `certs/`），**外部探测握手成功后才开始分配**。节点列表里"健康"栏看到"在线"、没有"尚未探测 / 对外不可达"即可。申请不到证书时在数据卷里放 `tls/fullchain.pem`、`tls/privkey.pem` 并在 compose 里打开 `RELAY_NODE_CERT_FILE` / `RELAY_NODE_KEY_FILE`（换文件会自动重读，坏文件保留已加载的证书）。

> 从节点不会跑安装向导，也不会自动更新（`NODE_ROLE=relay` 时程序不读 `AUTO_SETUP`，更新服务只在主节点）。从节点上不提供管理后台、登录、内嵌前端，对外只开 HTTPS。

## 4. 上线迁移（已有用户）

现有域名继续给主节点用，老用户要改地址。

1. 先把**主节点分配比例保持大于 0**（通用配置，默认 10）：旧地址的请求仍由主节点处理，比例为 0 会拒绝它们。迁移期间主节点转发上限（并发 / 带宽）按旧地址的实际流量设置，随用户迁走逐步下调，否则老用户会看到"服务繁忙"。
2. 激活至少一台从节点。**分配** 页签 → "给未分配的 Key 分配节点"：把打开开关之前建的 Key 批量分配（按剩余容量加权，主节点按比例）。
3. 用户的 Key 页面会显示分配的地址，地址变了的 Key 标"地址已变更"（14 天）；"使用密钥"和一键导入 CC Switch 用的就是各自节点地址。
4. 小白端：控制地址仍是现有域名，升级客户端后自动向服务器询问分配、把请求发往节点，用户不用操作。
5. 基本迁完再把比例调到 0（想让主节点完全不做中转的话）；保存前页面会列出还在主节点上的 Key 和用户数，要先把它们转走。

## 5. 日常运维

| 操作 | 位置 / 做法 |
|---|---|
| 看健康 | 节点页签：在线、对外不可达、错误率降级、时钟偏差、域名当前解析到哪里、证书剩余天数、未入账扣费条数。健康每 10 秒自动刷新 |
| 看日志 | **日志** 页签：实时向各节点查询（程序日志 / 错误记录 / 审核记录），离线或超时的节点单独标出，不入库；节点详情里有"最近日志" |
| 使用记录按节点 | 使用记录页的"节点"筛选和"节点"列（`node_id`，主节点自己转发的显示"主节点"） |
| 通知 | **通知** 页签：飞书机器人（地址和密钥加密保存、不回显）+ 邮件兜底，同时出事合并成一条，反复上下线合并成"不稳定"；"发送测试消息"验证 |
| 用户额度锁在掉线节点上 | 用户管理 → 操作 → "中转分配"：看各节点上锁定的额度和节点是否在线，离线的点"立即回收"（当场作废并放回；在线的发收回） |
| 调整比例 / 容量 | **通用配置**（整份保存，只影响新分配，已分配的不动）；"重新平衡"让没固定的小白端用户下次询问时重新分配 |

## 6. 升级、换机器、下线

**升级**（一台一台来，**主节点先升**，两边版本保持一致）：

1. 节点页签对这台点 **排空**：不再分配新用户和新 Key，进行中的请求照常结束，最长等"通用配置 → 排空最长等待"（默认 30 分钟），到时从节点关闭对外服务。想让这台的 API Key 用户不中断，可先把域名解析手动改到主节点（等 5 分钟，主节点只放行网关接口）。
2. 换镜像：`docker compose -f docker-compose.relay-node.yml pull && docker compose -f docker-compose.relay-node.yml up -d`。数据卷不动，长期密钥和证书缓存都在里面，重启后被认作同一台，不用重新激活。
3. 健康恢复后点 **取消排空**（解析改过的改回来）。

**换机器 / 重装**：

1. 在域名服务商处把域名解析改到新机器；新机器按第 3 节部署、注册（它是一台新节点，要读它自己的指纹）。
2. 旧节点页上点 **换机器**，选新节点、输入新节点指纹：旧节点停用（额度作废放回），域名、名称、带宽、区域和分到旧节点的 Key 一步转给新节点并激活。域名不变，用户不用改地址。

**下线一台**：先 **排空** → **转移 Key**（按分配规则自动选，或指定目标）→ **停用**。系统没有"删除节点"，也不会在停用时自动移走 Key。

**主节点换服务器**：只要主从通信根证书不变（`RELAY_KEY_DIR` 整个目录和 `relay-kek` 一起迁），从节点改一下 `RELAY_NODE_MASTER_ADDR` 就能重新连上，不用重新激活。

## 7. 密钥备份与恢复、被攻破时

**要备份的**（离线保存，和数据库备份分开存放）：

- 主节点：`RELAY_KEY_DIR`（默认 `<data>/relay-keys`，加密文件）**和**加密它的密钥文件（`RELAY_KEY_ENCRYPTION_KEY_FILE`）。两者缺一不可，丢了私钥所有从节点要重新激活。
- 从节点：数据卷里的 `identity/`（长期密钥）。丢了会变成一台新节点，要重新激活并用"换机器"转移域名和 Key。证书缓存丢了只是重新申请，注意 Let's Encrypt 的签发频率限制。

数据本地为准：不提供远程恢复，安装 / 升级不会自动备份。

**怀疑某台被攻破**：

1. 节点页点 **吊销证书**（填原因，进审计）：立即吊销它的证书并断开，退回待激活；吊销前签发的扣费凭证照常入账但全部标记待复核。
2. **转移 Key**（分到它的 Key 用户建议重置，Key 本身已经发给过它）。
3. **更换下发给它的敏感配置**（吊销成功后后台会弹出提醒，列出这三项）：审核接口 Key、提示词审计凭据、联网搜索 Key（以及它们引用的代理）是按节点加密下发、只在内存里的，被攻破后到各自的配置页换成新的；审核接口 Key 能调付费模型，建议用单独的、只开审核接口权限且有额度上限的 Key。
4. 换机器重新部署，不要原样恢复旧数据卷。
5. 域名证书私钥只在那台机器上，换掉域名证书（新机器重新申请）即可。

**根证书、中转票据、扣费凭证轮换**（**密钥轮换** 页签，三步）：生成预备版本（随配置推给所有在服务节点）→ 所有节点都收到后启用 → 新版本签发够久后停用旧版本。根证书轮换期间从节点的 `RELAY_NODE_ROOT_FINGERPRINTS` 新旧都写；预备版本还有节点没收到时"启用"按钮是灰的，页面会列出没收到的节点。

## 8. 容量、参数与磁盘规划

**HTTP 服务器参数**（从节点和主节点用同一组 `server.*`，环境变量 `SERVER_*`）：

| 参数 | 推荐 | 说明 |
|---|---|---|
| `SERVER_READ_HEADER_TIMEOUT` | 10 秒 | 防慢速请求头攻击 |
| `SERVER_MAX_HEADER_BYTES` | 65536 | 请求头上限，够用且挡超大头 |
| `SERVER_IDLE_TIMEOUT` | 120 秒 | 空闲连接回收；流式响应不受影响（按请求计） |
| 文件句柄 | 100000 | compose 里已设 `nofile` |

没有设置读 / 写总超时：流式响应和 WebSocket 会很长，由上游超时和客户端取消控制。

**内存**：Key 的**正缓存没有做**（每次请求现查主节点的认证缓存），负缓存最多 5 万条、30 秒过期；本地扣费队列默认最多 20 万条待发送记录（落盘，内存里只有索引）；其余是进行中请求的缓冲。小规格机器（2 核 / 4GB）适合几十个并发的流式请求，具体按压测定（WP19）。

**磁盘**（数据卷）：本机日志和记录总大小上限默认 2GB，超出先删最旧的；另有扣费队列（队列写不进去时从节点不接新请求，防止转发了记不上账）。心跳里报告剩余磁盘，**剩余磁盘低于几 GB 就要处理**。审核记录含输入内容摘录，属于敏感数据，磁盘和备份按敏感数据处理。

**固定参数**：租约 10 分钟（在线自动续期）、从节点证书 24 小时（自动续签换密钥）、中转票据 10 分钟、心跳 5 秒、15 秒判离线、时钟偏差超过 30 秒从节点拒绝服务（请校准 NTP）、证书剩 7 天提醒。完整表见设计第 19 节。

**转发参数要和主节点一致**：从节点配置文件里的 `gateway.user_message_queue`、`gateway.max_account_switches`、`gateway.antigravity_*` 等转发参数，部署时与主节点保持相同。

## 9. 独立外部监控

主节点自己挂了，主节点发的通知也就发不出来。另外找一台**不在主节点上**的机器或第三方监控服务：

- 每分钟请求主节点站点的 `/health`，连续 3 次失败告警（飞书 / 短信），并同时检查 `RELAY_MASTER_LISTEN_ADDR` 的 7443 端口是否可连；
- 从节点由主节点的外部探测负责（握手 + `/health`，连续 3 次失败标记对外不可达并通知），不需要额外配置；若想对从节点也做独立监控，直接对它的域名 `https://<域名>/health` 做同样检查。

## 10. 故障速查

| 现象 | 处理 |
|---|---|
| 页面上"运行状态"是"未配置 / 启动失败" | 看页面上的原因：多半是主节点没配 `RELAY_MASTER_LISTEN_ADDR` 或加密密钥 |
| 从节点日志卡在注册 | 后台"待激活"里有没有这台；根证书指纹是否抄对 |
| 激活被拒"指纹不一致" | 指纹要在从节点本机日志里读，不是复制页面上那行 |
| 激活提示域名没解析到这台 | 解析还没生效（TTL）或写错 IP；确认后可勾"仍然激活" |
| 节点显示"对外不可达" | 443 是否开放、域名解析、证书是否申请成功（日志、证书剩余天数）；探测错误原样显示在健康栏 |
| 节点显示"时钟偏差" | 校准系统时间（NTP），超过 30 秒它会拒绝服务 |
| 节点"错误率降级" | 查日志页签的错误记录；恢复到 15% 以下连续两次自动恢复 |
| 节点离线、用户额度被锁 | 用户管理 → "中转分配" → 立即回收；或节点页"回收额度" |
| 关总开关被拒"还有节点在服务" | 先排空并停用所有从节点 |
| 小白端连不上节点 | 客户端会向服务器报告并换一台（同一请求最多换一次）；多名用户报告同一台时主节点暂停给它分配 5 分钟并通知 |
