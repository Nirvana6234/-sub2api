## 1. 目标

本软件收敛为一个单用户、单管理员的本机中转管理工具。Codex、Claude、Gemini、Grok 等客户端始终连接本机 Sub2API，本机 Sub2API 负责账号、外部来源、代理和调度。

客户端不再直接连接云端或其他来源。用户在软件中切换的只是本机 Sub2API 的调度配置，因此切换来源后不需要重启客户端。

## 2. 身份模型

本机只有一个身份：本机所有者，同时拥有管理员权限和使用权限。

不在本机工具中保留注册、用户列表、用户余额、贡献额度、抽成、共享房间和多人权限。管理员会话和敏感凭据使用本地安全存储，软件启动后自动复用。

## 3. 资源模型

### 3.1 个人账号

个人账号是用户导入的 OAuth、CPA、RT、AT、auth.json、API Key 等账号。个人账号默认优先供本机使用。

每个账号复用 Sub2API 原生字段和调度能力：

- 平台、账号类型和分组
- 启用状态、健康状态、额度和冷却时间
- 账号优先级
- 调度权重/负载因子
- 最大并发
- 模型映射
- 账号级代理
- 批量测试、批量编辑和批量删除

### 3.2 外部来源

外部来源是用户添加的第三方 API 或中转站，包括 OpenAI、Claude、Gemini、Grok、其他 Sub2API 和 OpenAI 兼容服务。

外部来源使用 Sub2API 支持的渠道或 API 账号实体，不在 WPF 工具中重新实现一套调度器。可配置地址、密钥、平台、模型组、优先级、权重、并发、代理、健康检测和模型映射。

## 4. 调度顺序

分类顺序固定为：

```text
个人账号
  -> 个人账号没有可调度候选
外部来源
```

个人账号内部和外部来源内部都由 Sub2API 原生调度器选择。候选排序沿用优先级、负载、排队、错误率、首包延迟、额度余量、会话粘性和其他现有因素。

没有可调度候选包括停用、过期、额度不足、限流、冷却、并发已满、健康检查失败、模型不支持等情况。参数错误、模型不存在和鉴权格式错误不应无条件切换到其他候选。

界面同时显示“优先级”和“调度权重”。优先级数值越小越先参与调度；调度权重对应 Sub2API 的 load_factor/负载能力，不能误解释成简单的固定百分比。

## 5. 代理

代理属于账号或外部来源的属性。编辑个人账号时可以选择直连、已有代理或新建代理并绑定。代理凭据本地加密保存，调度请求由 Sub2API 统一使用该代理。

## 6. 客户端入口

客户端只保存一次本机入口：

- Codex、Grok：`http://127.0.0.1:8080/v1`
- Claude：`http://127.0.0.1:8080`
- Gemini：使用本机 Sub2API 的兼容入口

工作台运行期间可以将客户端配置切换到本机入口；工作台退出时恢复启动前配置；下次启动自动恢复上次工作状态。来源切换只修改本机 Sub2API 路由，不重写客户端上游。

## 7. 中转中心界面

不再显示技术型“服务概览”，不向用户展示本机服务状态、网关地址、端口、请求数、Docker/原生方式和组件信息。

中转中心当前提供三个页签：

1. 外部来源：上方“客户端路由”是唯一生效入口；下方“外部来源库”通过下拉选择来源，并在同一详情区新增、编辑、检测或删除。
2. 个人账号：展示个人账号健康与调度属性，个人账号始终先于外部来源参与候选。
3. 服务操作：只保留打开后台、重启、停止和操作日志等直接操作。

客户端路由与来源库职责严格分离。来源库中的选中状态只决定当前编辑对象，不会改变 Codex、Claude、Gemini 或 Grok 的实际路由。正在被任一客户端路由使用的来源必须先完成替换，才能删除。

局域网后台与局域网中转暂不进入新界面和路由候选。旧配置仅作为兼容数据保留，不主动删除。

页面顶部按全部、Codex、Claude、Gemini、Grok 筛选。服务启动、健康检查和故障恢复在后台静默完成；只有无法启动或无法访问时才显示可操作的错误提示。

APP 启动时只检查一次本机 Sub2API；服务未运行且存在本机控制脚本时自动启动，页面切换不会重复启动或刷新。

本机管理员使用回环控制会话，不展示邮箱密码输入。启动脚本为每台电脑生成独立高熵令牌，并用 Windows DPAPI 按当前用户加密保存。Sub2API 仅在显式配置该令牌时开放本机控制接口，并依据 TCP 对端地址严格限制为 loopback；云端未配置令牌时接口返回不存在。

## 8. 数据边界

本机数据库和本机配置是唯一权威来源。不读取远程备份，不使用远程数据库覆盖本地数据，远程服务只作为本机配置的外部来源。

迁移和发布时不携带账号数据库、日志、`.env`、本地会话、用户路径和个人密钥。

## 9. 实施顺序

1. 将所有客户端入口固定到本机 Sub2API。
2. 将现有来源迁移为本机外部来源，保留名称、平台、地址、密钥、代理和模型映射。
3. 将个人账号导入、代理绑定、权重和健康状态接入 Sub2API 原生接口。
4. 实现个人账号优先、外部来源后置的候选阶段调度。
5. 将连接中心和账号中心收敛为中转中心界面。
6. 测试来源切换、个人账号耗尽、代理失败、外部来源切换、服务重启和客户端不重启场景。

## 10. 验收标准

- 客户端始终只连接本机入口。
- 切换来源不修改客户端直连地址，不需要重启客户端。
- 个人账号可单独绑定代理、优先级和调度权重。
- 个人账号不可用时才进入外部来源。
- 个人账号和外部来源都使用 Sub2API 原生调度状态。
- APP 不显示用户不关心的本机服务技术信息。
- 工作区迁移不包含账号数据库、日志、`.env` 和个人路径。
