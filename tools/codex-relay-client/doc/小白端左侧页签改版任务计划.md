## 1. 目标

把单页滚动的仪表盘改成**左侧页签**：

```
┌──────────┬───────────────────────────────────────────┐
│ 共飞AI助手 │  <当前页标题>                     🔔  刷新  │
│          │                                           │
│ ▣ 仪表盘  │  ……页面内容……                              │
│ ◉ Codex • │                                           │
│ ✳ Claude  │                                           │
│ ☾ Kimi    │                                           │
│ ◎ 账户  ! │                                           │
│ ┄┄┄┄┄┄┄┄ │                                           │
│ (项目)    │  ← F11 预留，本次不做                       │
│ (聊天)    │  ← F12 预留，本次不做                       │
│ ⚙ 设置    │                                           │
│ v0.x 你好x │                                           │
└──────────┴───────────────────────────────────────────┘
```

背后的意图（这次改版要让架构承接的东西）：

1. **一个工具一页**。本机 relay 已经按调用方分组（Codex 走 `SetGroup`、Claude Code 走 `SetClaudeGroup`），
   每个工具有自己的分组、状态、应用/还原。现在界面上 Claude Code 只是分组卡片底下的一个复选框；
   Kimi Code CLI 是第三个工具。以后再接工具＝加一页 + 一个接入实现，而不是往一个 VM 里再塞 300 行。
2. **拆掉 `DashboardViewModel` 这个 2066 行的上帝对象**，按页拆，状态和它的防护一起搬。
3. **公共部分独立**：仪表盘（总览）、账户、设置。给 F11 项目中心、F12 聊天、F8 诊断、
   主从分流的「线路」状态留位置。
4. **只剩一个 UI 头**，不再有「两个头都要改、漏改不报错」的坑。

## 2. 各页内容

| 页 | 内容 | 从现在哪里来 |
|---|---|---|
| 仪表盘（默认页） | 余额/今日用量摘要；每个工具一张状态卡（状态 + 当前分组 + 一个主按钮）；近 7 日趋势；余额偏低提醒；预留「线路」一行 | 账户卡、用量卡、趋势卡 |
| Codex | 启动/安装/修复；Codex 分组与倍率、「模型」白名单、自动分组配置；上下文压缩开关与累计节省；「保持客户端运行」提示 | 主按钮卡 + 分组卡上半 |
| Claude | 接入 Claude Code / VS Code 插件总开关；插件用的 Claude 分组；Claude 模型与思考强度（注明「Codex 用 Claude 分组时也按此设置」）；接入状态 | 分组卡下半的插件区 + Claude 模型设置 |
| Kimi | 接入 Kimi Code CLI 总开关；Kimi 分组；模型；接入状态 | 新增 |
| 账户 | 用户名、余额/冻结、充值、订阅、按模型消费、退出登录 | 账户卡、订阅卡、按模型列表 |
| 设置（底部） | 随系统启动、版本/检查更新、联系我们、公告入口；F8 诊断以后放这 | 页脚与顶栏零碎项 |

导航徽标：Codex 需重启/修复→红点；Claude/Kimi 接入失败→「!」；余额偏低→账户「!」；公告未读→铃铛。都绑定已有状态属性。

执行中与原计划的出入（均已落地）：

- 页面不是靠 `DataTemplate` 映射，而是 `DashboardView` 构造时**显式 new 出 6 个页面**、按 `ClientPage` 切换——同样不依赖反射，裁剪安全，且更简单。
- **不记忆上次停留的页**：每次登录都落在仪表盘（小白用户打开窗口先看总览更合适），登出时也回到仪表盘。
- 仪表盘、设置页的大部分内容已在 T2 一并完成，T12 只剩「线路」预留与徽标补齐。
- T3 的「轮询不挂在页面上」在 T2 已满足：`DashboardView` 现在是登录后的外壳，计时器不随页面切换停止。T3 因此收窄为只抽「每轮刷新的记账」（见 T3）。
- T6 不再单独重命名：抽走账户/用量/Claude/刷新记账之后，`DashboardViewModel` 剩下的就是 Codex 页的 VM，改名只会让所有测试大面积改动而无实际收益。

### T8 Kimi Code CLI 调研（**闸门**：T9–T11 按结论做）

在真实安装上确认，结论写回本文件 §5：

1. **哪个产品**：`kimi-code`（`~/.kimi-code/config.toml`，`KIMI_CODE_HOME` 可改目录）还是 `kimi-cli`（`~/.kimi/config.toml`）；当前维护的是哪个；支持一个还是两个（D5）。
2. **哪种 provider type 能端到端跑通真实 kimi 分组**：

   | provider `type` | 本机 relay 路由 | 后端 |
   |---|---|---|
   | `anthropic` | Messages | `/api/v1/paw/messages`（需确认「仅限 Claude Code」分组检查不会拒它） |
   | `kimi` / `openai` | Chat Completions | `/api/v1/paw/chat/completions`（relay **目前没有**这条路由） |
   | `openai_responses` | Responses | `/api/v1/paw/responses` |

3. **模型条目**：分组接受的模型 id（按分组白名单或 `kimi-k2.5` 之类），`max_context_size`、`capabilities` 该写什么。
4. **凭据**：自定义 provider 用 `api_key`（写 relay 的本机随机 token）是否就不再要求 Kimi 登录；`api_key_env` 是否更合适。
5. **生效时机**：配置启动时读取、运行中需 `/reload`；确认 relay 端口/token 跨启动固定后，正在运行的 CLI 不受影响。

### T9 relay 增加「调用方」维度

- 现状：relay 按**协议**选分组槽（Messages→Claude 槽，其余→Codex 槽）。Kimi 若走 `/v1/messages` 或 `/v1/responses`，会**静默计费到 Claude 或 Codex 的分组**。
- 改为按**调用方**：Kimi 走独立前缀（例如 `/kimi/v1/...`），有自己的分组槽和 `SetKimiGroup`；路由表加 T8 选定协议的那一条。
- **`/v1/responses` 与 `/v1/messages` 保持逐字节不变**——用户机器上已写好的 `~/.codex/config.toml`、`~/.claude/settings.json` 指向的就是这两个无前缀路径。
- 目前「未选分组即拒绝」与错误体形状按 `protocol == Messages` 判断，要改为按调用方判断。
- Origin/Host 校验、常量时间比对、UA 一致性（`enforceSessionBinding` 按 IP+UA 校验）等闸门对新前缀同样生效。
- 验收：现有 `LocalPawRelayTests`、`LocalPawRelayMessagesTests` 不改全绿；新增并发用例——Claude 与 Kimi 同时请求，上游收到的 `X-Paw-Group-Id` 各自正确。
