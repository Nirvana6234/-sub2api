# 工作区迁移说明

## 目录

```text
E:\edge_web__trans
├─ tools\manufactor_app\ai-switch-gui   共飞 AI 工作台源码、测试和参考组件
├─ sub2api                               Sub2API 源码、前端依赖和部署文件
├─ .local\pgsql                         本机原生模式 PostgreSQL 运行文件
├─ .local\redis                         本机原生模式 Redis 运行文件
├─ start-sub2api-local.ps1               本机原生启动脚本
├─ stop-sub2api-local.ps1                本机原生停止脚本
├─ Start-Sub2API.bat                     原生启动入口
├─ Start-Sub2API-Docker.bat              Docker 启动入口
├─ Sub2API-Control.ps1                   Docker 控制脚本
├─ Sub2API-Native-Control.ps1            原生控制脚本
└─ doc                                   设计文档和迁移文档
```

`doc/历史设计资料` 保存了原工作区已有的产品设计、UI 原型和访问说明；`doc/中转中心单用户本机架构设计草稿.md` 是本轮讨论形成的新版草稿。

## 已排除内容

迁移保留了源码和运行所需依赖，但没有复制以下本地状态：

- Git 元数据
- Sub2API `deploy/data`、`postgres_data`、`redis_data`
- `.env` 文件
- 数据库、账号、会话和 API 密钥
- 日志和临时输出
- APP 的 `bin`、`obj` 和旧构建目录
- APP 原来的 `native-path.txt` 路径配置

发布版只复制到 APP 的 `artifacts/publish/LanAi.Workspace`。新工作区的 `native-path.txt` 指向 `E:\edge_web__trans`。

## 本机原生启动

```powershell
Set-Location E:\edge_web__trans
.\start-sub2api-local.ps1
```

脚本会在新工作区创建新的 `.local\pgdata`、`.local\redis-data` 和 `.local\sub2api-data`。原工作区数据库不会被复制或覆盖。

## APP 构建

```powershell
Set-Location E:\edge_web__trans\tools\manufactor_app\ai-switch-gui
dotnet build .\LanAiWorkspace.sln -c Release
dotnet test .\LanAiWorkspace.sln -c Release
```

## 前端依赖

前端依赖已在新工作区按锁文件重建。需要重新安装时：

```powershell
Set-Location E:\edge_web__trans\sub2api\frontend
$env:CI = "true"
pnpm install --frozen-lockfile
```

## 说明

本迁移是复制，不删除 `E:\web_transform` 原工作区。后续修改应以新工作区为主，确认运行和数据无误后再考虑清理旧目录。
