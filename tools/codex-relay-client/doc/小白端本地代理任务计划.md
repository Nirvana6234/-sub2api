# 小白端「本地代理」—— 任务计划

> 状态：计划稿（2026-09-23），未开工。本文件只写当前结论，未定事项集中在 §2。
> 取代左侧页签里的 Kimi 占位页；原 Kimi Code CLI 计划（页签改版计划 T8–T11）搁置。

## 1. 需求（已与用户确认）

- 左侧「Kimi」页签改为「**本地代理**」。页面列出用户在中转站上**自己的账号**（贡献账号），按账号类型识别；
  **先只支持 Codex 账号**（`platform=openai` 且 `type` 为 `oauth` / `setup-token`），其他类型显示「暂不支持」。
- 用户在页面上**主动**开启某个 Codex 账号的本地代理后，Codex 的请求**不再发往中转站**，由客户端带着该账号身份**直发官方**
  `chatgpt.com/backend-api/codex/responses`。客户端只在中间做上下文压缩，**不复刻中转站的身份封装**。
- 与中转站**二选一**：开启期间仪表盘 Codex 卡片显示「正在使用本地代理：<账号名>」，不再显示分组/倍率。
- 仪表盘增加「本地代理用量」。
- **凭据**：新增后端接口，只给账号所有者下发**短期 access token** 与 `chatgpt_account_id`；**refresh token 永不离开服务器**，
  刷新仍由中转站唯一负责（OpenAI 的 refresh token 用一次换一次，两边各自刷新会互相作废）。
- **出错只提醒、不回退**：本地代理是用户主动切的，出错时通知 + 页签红点 + 页面写明原因，**不自动切回中转站**（自动切回会开始扣余额，用户不知情）。

## 2. 默认执行、可随时改的决定

| # | 问题 | 默认 |
|---|---|---|
| P1 | 二选一的范围 | **只管 Codex**。Claude Code 插件照走中转站（本地代理只支持 Codex 账号）。 |
| P2 | 该账号同时在中转站共享池里被别人调度 | **v1 不摘出共享池**，页面提示「该账号同时在中转站共享使用，额度会被共用」。要摘出需再加后端改动（开启时暂停调度、关闭时恢复），见 L1-可选。 |
| P3 | 开启时 Codex 正在用 Claude 分组 | **不允许开启**，提示先在 Codex 页切到 GPT 分组。ChatGPT 账号跑不了 Claude 模型，而模型写在 config.toml 里，改它要重启 Codex。 |
| P4 | 重启客户端后 | **记住并恢复**本地代理（用户的主动选择），启动时在仪表盘明示正在使用本地代理。账号已失效则按「出错」处理。 |
| P5 | 余额与「今日用量」 | 仍是中转站数字，注明「不含本地代理」；本地代理用量单列。 |

## 3. 直发时客户端要做 / 不做什么（对照服务端透传路径的结论）

依据：`backend/internal/service/openai_gateway_passthrough.go`（`buildUpstreamRequestOpenAIPassthrough`、`forwardOpenAIPassthrough`）。

**必须做**（Codex 跑在「自定义 provider」模式而非 ChatGPT 登录模式，缺的由客户端补）：

- `Authorization` 换成账号 access token（Codex 带来的是本机随机假 key）。
- 加 `chatgpt-account-id`；FedRAMP 账号加 `x-openai-fedramp: true`。
- 请求头按服务端白名单 `openaiPassthroughAllowedHeaders` 透传（accept、accept-language、content-type、conversation_id、openai-beta、
  user-agent、originator、session_id、x-codex-beta-features、x-codex-installation-id、x-codex-turn-state、x-codex-turn-metadata、
  x-codex-window-id 等），**不是全部原样**——否则假 key 和过滤器的 `x-context-filter-*` 统计头也会发出去。
- `x-codex-beta-features` 缺省时补默认值（远程压缩 v2，对应 `applyOpenAICodexBetaFeatures`）。
- 剥掉 `OpenAI-Beta` 里过时的 `responses=experimental`（`stripOpenAILegacyResponsesBeta`）。
- `accept`：默认 `text/event-stream`；`/compact` 为 `application/json`。

**建议做**（字节级小改动，对应 `normalizeOpenAIPassthroughOAuthBody`；正常 Codex 请求不会触发，防新版本多带字段被 400）：

- `store=false`、`stream=true`（`/compact` 相反：删除这两个字段）。
- 删 `openAIChatGPTInternalUnsupportedFields`：`chat_template_kwargs`、`user`、`metadata`、`prompt_cache_retention`、`safety_identifier`、
  `stream_options`、`truncation`、`stop_sequences`。
- `prompt` 并入 `input` 后删除；删 `commands`；`reasoning.mode`（pro→effort=max，其余删除）。

**不做**（中转站多用户共用多账号才需要）：session/conversation 跨用户隔离、指纹收敛、账号身份写 client_metadata、统一 UA/version、
换号重试、容量错误码改写、工具名别名、补 instructions、zstd 压缩。直连时 Codex 收到的是官方原始错误，与 ChatGPT 登录模式一致。

**路径**：`/v1/responses` 及子路径 `/compact`、`/input_tokens` 映射到 `/backend-api/codex/responses[/…]`，同一套处理；
其余路径继续拒绝并记日志。依据：本机全部真实 `client.log` 里没有一条「本机 Relay 拒绝」，自定义 provider 下 Codex 只调过 `/v1/responses`；
旧 `/responses/compact` 上游已下线（404），压缩 v2 走 `/responses`（体内 `compaction_trigger` + beta 头）。

## 4. 任务

```
L0（真账号验证）─┐
L1（后端接口）───┼─► L2（客户端契约）─► L3（relay 直发）─► L4（用量）─► L5（界面）─► L6（出货）
```

每个任务单独提交，提交前后端 `go test ./...`（相关包）/ 客户端 `dotnet test LanAi.RelayClient.sln -c Release` 全绿。

### L0 真账号验证（阻塞 L3 的细节）

需要一个真实的、挂在测试账号名下的 Codex 贡献账号。用抓包或临时日志确认：

1. 自定义 provider 模式下 Codex 实际发出的请求头：有没有 `session_id`、`x-codex-beta-features`、`originator`、`version`。
2. 按 §3 补齐后，直发官方能跑通：普通对话、工具调用、长会话触发的远程压缩各一次。
3. 官方 401（token 过期）/ 429（额度用尽）/ 容量不足时的真实返回形态，供 L3 的错误提示用。

### L1 后端：下发本地代理凭据

- `POST /api/v1/account-contributions/:id/local-proxy-token`（POST 以免被缓存；挂在现有 `account_management` 功能开关下）。
- 复用 `ownedAccount`：只有账号所有者能取；账号须 `UsesOpenAICodexProtocol` 且 `IsOpenAI`，状态可用；影子账号按
  `resolveCredentialAccount` 解析到母账号。
- 经 `OpenAITokenProvider.GetAccessToken` 取 token（服务端负责刷新、带锁）；返回 `access_token`、`chatgpt_account_id`、`fedramp`、
  `expires_at`、账号名。**绝不返回 refresh_token**。
- 响应头 `Cache-Control: no-store`；按用户限频；审计日志只记「谁、哪个账号、何时」，**不记 token**。
- 测试：非所有者 403、非 Codex 账号 400、功能关闭 403、响应里没有 refresh_token、限频生效。
- **L1-可选（P2 改为摘出共享池时才做）**：开启/关闭本地代理时暂停/恢复该账号的共享调度。

### L2 客户端：Server 契约

- `IRelayServerClient` 新增：列出贡献账号（只取 id、名称、platform、type、状态、计划类型等非敏感字段）、取本地代理凭据。
- 契约测试用真实服务器响应形状钉住；功能未开通（403）要能区分出来，页面显示「账号未开通此功能」。

### L3 relay 直发模式

- `LocalPawRelay` 增加 Codex 路由的**上游模式**：中转站（现状）/ 本地代理（账号 id）。切换只改 relay 内部状态，
  **Codex 不重启、config.toml 不动**（端口与假 key 不变）。
- 凭据按请求现取（同 JWT 的做法，**不做启动时快照**），`expires_at` 前或遇官方 401 时向中转站重取一次；
  401 重试只在响应尚未开始写回时进行。
- 按 §3 构造请求；Claude Code 的 `/v1/messages` 路由完全不受影响。
- 官方的错误原样回给 Codex，同时向界面报告「本地代理出错：原因」（通知 + 红点），**不回退中转站**。
- 用于官方的 HttpClient 与连中转站的分开：中转站那边的 UA 一致性（`enforceSessionBinding`）不受影响。
- 测试：头白名单/替换/剥离逐条；`/compact` 的 accept 与体改写；体改写对正常请求**逐字节不变**；401 重取一次；
  模式切换后下一轮即生效；并发请求下不串模式。

### L4 本地代理用量

- 边转发边解析 SSE，在 `response.completed` 事件里取 `usage`（input/output/cached/reasoning tokens），**不缓存整段流**。
- `LocalProxyUsageStore`：按天、按账号累计请求数与 token，原子写，照 `ContextFilterUsageStore` 的做法（含饱和加法）。
- 压缩节省量沿用现有统计。
- 测试：分块边界切在事件中间、没有 usage 的事件、被中断的流。

### L5 界面

- `ClientPage.Kimi` → `ClientPage.LocalProxy`，页签名「本地代理」。
- 本地代理页：账号列表（名称、类型、计划、状态）；Codex 账号可「开启/关闭」，同时只能开一个；其他类型「暂不支持」；
  功能未开通时说明原因；开启中显示状态、最近错误、本地用量；P2 的共享提示；P3 的拦截提示。
- 仪表盘：Codex 卡片显示「正在使用本地代理：<名称>」；新增「本地代理用量」卡；今日用量卡注明不含本地代理。
- Codex 页：本地代理开启时分组切换置灰并说明；托盘状态行改为本地代理；出错时本地代理页签红点。
- 偏好：记住开启的账号 id（P4），登出清除。

### L6 出货

- 裁剪发布 win-x64 / osx-arm64 按 CI 标准无新增警告；UTF-16LE 搜到新文字；用假数据渲染脚本逐页截图核对；
  真机按 L0 的三项再走一遍。

## 5. 风险

| 风险 | 后果 | 对策 |
|---|---|---|
| 客户端拿到的 token 被本机其他程序读到 | 账号被盗用 | 只存内存、不落盘；只下发短期 access token，不下发 refresh token |
| 同一账号同时被中转站共享调度 | 额度被抢、可能触发风控 | P2 明示；需要时做 L1-可选 |
| Codex 新版本在自定义 provider 下改了请求形态 | 直发 400 | §3「建议做」的体改写兜底；错误原样显示便于定位 |
| 用户以为出错会自动回到中转站 | 以为在用却没在用 | 出错通知写明「本地代理未生效，未切回中转站」 |
